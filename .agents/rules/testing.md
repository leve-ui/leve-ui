# テスト

コンポーネントを追加・変更したら、必ず以下の 3 つを揃える。テストのない実装は完了とみなさない。

| 種類           | 場所                                             | ツール               | 確認すること                                                         |
| -------------- | ------------------------------------------------ | -------------------- | -------------------------------------------------------------------- |
| ユニットテスト | `packages/components/<name>/src/<name>.test.tsx` | Vitest + `createDOM` | 描画結果、ARIA 属性、data 属性、props の受け渡し、状態ごとの出し分け |
| ストーリー     | `apps/storybook/stories/<name>.stories.tsx`      | Storybook            | 代表的な状態ごとに 1 ストーリー（Default / Disabled / Open など）    |
| E2E            | `apps/e2e/tests/<name>.spec.ts`                  | Playwright           | キーボード操作、フォーカス移動、実ブラウザでのイベント               |

`packages/utils` に関数を追加した場合も、同じディレクトリに `<file>.test.ts` を書く。

## ユニットテストで最低限確認すること

- 各パーツが描画され、`data-leve-*` 属性が付いていること。
- APG で必須の `role` と `aria-*` 属性が正しい値で出力されること（ID の関連付けを含む）。
- 状態ごとの `data-state` と表示の出し分け。
- `class` や `aria-label` などの任意の props が要素に渡ること。
- 制御（`bind:`）と非制御（`default*`）の両方の動作（状態を持つ場合）。

## E2E で最低限確認すること

- APG に書かれたキーボード操作（1 操作につき 1 テストケース）。
- フォーカスの移動と復帰。
- 外部リソース（画像 URL など）は `page.route` でモックし、ネットワークに依存させない。

## 禁止事項

- テストが落ちたときに、テストを消したり弱めたりして通すこと。実装を直すか、仕様変更ならユーザーに確認する。
- テストを書かずに作業を完了とすること。

具体的な書き方（`createDOM` の使い方、story ID の決め方、Playwright の書き方）は `write-tests` スキル（`.agents/skills/write-tests/`）を参照する。

# 0017. Write commit messages in English

- Status: Accepted
- Date: 2026-11-10
- Related: [0012](0012-conventional-commits-with-commitlint.md), [0015](0015-run-commitlint-and-biome-in-git-hooks-with-lefthook.md)

## Context

[0012](0012-conventional-commits-with-commitlint.md) adopted Conventional Commits and allowed Japanese subjects. The repository is now public on GitHub, and its description, ADRs, and package metadata are already in English. Commit messages appear in changelogs generated by Changesets and in the public history, where Japanese excludes most potential contributors.

## Considered Options

1. **Keep allowing Japanese** — Easier for the current maintainers, but inconsistent with the rest of the public-facing project.
2. **English by convention only** — No tooling, but easy to forget, especially for AI agents.
3. **English enforced by commitlint** — Mechanically checked on commit (lefthook) and in CI.

## Decision

This ADR supersedes [0012](0012-conventional-commits-with-commitlint.md). The full commit policy is:

- Commit messages follow Conventional Commits (`@commitlint/config-conventional`).
- Scopes are generated from directory names in `commitlint.config.ts` (`packages/components/*`, `apps/*`, `tooling/*`, plus fixed values).
- The header and body must be written in English. A local commitlint plugin rejects non-ASCII characters (`header-english`, `body-english`).
- The default `subject-case` rule applies again: subjects are imperative and start with a lowercase letter (e.g. `add delayMs to Fallback`).
- Headers are limited to 100 characters.

## Rationale

- English matches the other public-facing parts of the project (README summary, ADRs, package descriptions).
- Enforcing it with commitlint means neither humans nor AI agents need to remember it.

## Consequences

- The initial commit (`9769371`) has a Japanese message. It is not rewritten, because `main` has already been pushed.
- The ASCII check also rejects non-ASCII characters such as emoji and accented names in the body. Co-author trailers use ASCII names.
- Pull request descriptions and code review comments may still be written in Japanese.

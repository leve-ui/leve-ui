# Switch

A control that turns an option on or off.

Switch follows the [Switch WAI-ARIA design pattern](https://www.w3.org/WAI/ARIA/apg/patterns/switch/).

<Demo id="switch/default" />

## Installation

Install the all-in-one package:

```sh
pnpm add @leve-ui/core
```

Or only this component:

```sh
pnpm add @leve-ui/switch
```

## Anatomy

```tsx
import { Switch } from '@leve-ui/switch'; // or '@leve-ui/core'

<Switch.Root>
  <Switch.Label />
  <Switch.Control>
    <Switch.Thumb />
  </Switch.Control>
  <Switch.HiddenInput />
</Switch.Root>
```

| Part | Element | Description |
| --- | --- | --- |
| `Switch.Root` | `<div>` | Wraps the parts and holds the on/off state. Not interactive. |
| `Switch.Label` | `<label>` | The label. Clicking it toggles the switch. |
| `Switch.Control` | `<button>` | The switch itself, with `role="switch"`. |
| `Switch.Thumb` | `<span>` | The thumb inside the control. Decorative. |
| `Switch.HiddenInput` | `<input type="checkbox">` | Optional. Sends the state with a native `<form>`. |

Inside a `Field.Root`, use `Field.Label` instead of `Switch.Label`. The Field provides the IDs, the description and the `disabled` / `required` / `invalid` states.

## API Reference

### Root

<PropsTable component="switch" part="Root" />

| Data attribute | Value |
| --- | --- |
| `data-leve-switch` | Always present |
| `data-state` | `"checked"` \| `"unchecked"` |
| `data-disabled` | Present when disabled |

The state is uncontrolled with `defaultChecked`, or controlled with `bind:checked`. `onCheckedChange$` is called when the user turns the switch on or off.

Inside a Field, the IDs come from the Field and `ids` is ignored ([ADR 0024](https://github.com/leve-ui/leve-ui/blob/main/adr/0024-wire-field-ids-and-descriptions-from-the-field-root.md)).

### HiddenInput

<PropsTable component="switch" part="HiddenInput" />

| Data attribute | Value |
| --- | --- |
| `data-leve-switch-hidden-input` | Always present |
| `data-state` | `"checked"` \| `"unchecked"` |
| `data-disabled` | Present when disabled |

The hidden input follows the checked, `required` and `disabled` states, so native form submission and `required` validation work ([ADR 0026](https://github.com/leve-ui/leve-ui/blob/main/adr/0026-participate-in-native-forms-through-a-hiddeninput-part.md)). It is positioned absolutely with an inline style, so give `Switch.Root` `position: relative`.

## Accessibility

Complies with the [Switch WAI-ARIA design pattern](https://www.w3.org/WAI/ARIA/apg/patterns/switch/).

- Name the switch with `Switch.Label`, `Field.Label`, or `aria-label` / `aria-labelledby` on `Switch.Control`.
- `Switch.Control` is a `<button type="button">` with `role="switch"` and `aria-checked` (`"true"` or `"false"`), and `aria-required` when required. Inside a Field it also renders `aria-describedby` and `aria-invalid`. When disabled, it uses the native `disabled` attribute, so it is not focusable.
- Do not change the label text with the state. The state is conveyed by `aria-checked`.
- `Switch.Thumb` and `Switch.HiddenInput` are hidden from assistive technologies with `aria-hidden="true"`. The hidden input is not in the tab sequence.
